# 运行性能与输入适配

用于低帧率拖动、弹丸密集卡顿、重复场景更新和近景 HUD 问题。保留当前玩法、资源及视觉约束，不默认通过减少射击、伤害、人数或关闭阴影换取性能。

## 先分清问题与证据

- 分开记录包体字节、解压耗时、真实可操作首帧、帧时间和内存；压缩后更小不代表运行更快，解压更快也不代表场景加载更快。
- 比较同一设备、视口、缓存与前台可见状态。后台或被遮挡标签页可能被节流，不能把此时的低 FPS、长加载直接解释为游戏瓶颈；把假设与已确认原因分开记录。
- 操作次数测试可以证明减少遍历或 Transform 写入，不能换算为真机 FPS 提升比例。没有真机对比时，不声称掉帧已完全消除。

## 低帧率拖动

- 沿输入事件、位移累计、消费、动画方向及帧末清理追踪同一数据。多次移动事件直接赋值会覆盖前面的位移；未消费输入在 lateUpdate 或松手时清零也可能丢掉最后一段拖动。
- 相对位移应累计、只消费一次，不再乘 deltaTime。持续速度、加速度和平滑追赶才按实际时间推进。固定每帧 16 ms 等步长在掉帧时会拖慢响应。
- 若动画也读取方向，把待消费位移与动画方向分开，避免移动组件提前清零让跑步动画失效。取消、禁用、重新按下的清理规则与正常松手分别处理。
- 需要保留旧平滑手感时，可采用有上限的时间步进；明确长时间暂停后的处理，不让追帧循环无界增长。不要把某项目的步长、灵敏度和质量参数设为通用值。
- BDD 覆盖相同总输入在不同帧率/事件批次下的目标位置、相同真实时长的追赶距离、同帧松手、取消、方向反转及道路边界。测试时间长度必须一致。

## 子弹与重复场景更新

- 跳过已隐藏或回收弹丸的移动与碰撞同步；一组子弹全部失活后及时回收父组。命中与回收须幂等，复用时重置命中标志、方向和位移缓存。
- 高数量活跃数组若采用尾部交换删除，需要更新交换节点索引并验证迭代不漏项；不能仅把 findIndex 换掉而破坏计数、暂停、清池和复用流程。
- 已落稳筹码、未变化队形和其他静止对象不要每帧重复写相同 Transform；使用符合坐标精度的比较，并覆盖落下、增员、减员、换父节点及重新启用。
- 同帧多处需要相同组件列表时可共用一次枚举，但确认期间没有需要立即纳入的生成/销毁。稳定骨骼可缓存查找结果、每帧读取动态世界位置；替换或销毁节点时使缓存失效。无头骨模型保留包围盒等实际可用回退。
- 缓存和对象池不等于无限保留资源。检查引用生命周期、停用后碰撞体、清池重复调用和失败/胜利重开。

## 近景与竖屏血条

- 镜头变化后重新核对世界空间血条的屏幕投影、整体尺寸与顶部品牌/CTA 遮挡，不能只检查锚点在屏幕内。
- 在允许的 UI 范围内为血条及数字提供可见区域约束；若采用屏幕空间替代显示，保留实际生命比例，避免与原血条同时出现，死亡及横竖屏切换都正确恢复/隐藏。
- 验证开局、走近、受击、死亡和方向切换；不通过再次拉远镜头取消用户刚确认的近景。屏幕约束可能改变相对头顶位置，应以实际截图确认效果。

## 压缩与交付

- 解码器优化先核对字节一致性、错误输入及输出大小边界；共享 Buffer/TypedArray 或绕过 JSON 中间转换时检查调用方仍兼容，不能仅靠一次成功解压。
- 只有实际测量支持时才替换压缩算法；压缩率、启动 CPU 和最终字节预算共同决定方案，不把某算法固定为最佳。
- 最终验收对象是本次交付 HTML：确认修复进入编译后的有效载荷、资源引用和压缩后完整性，记录精确字节及哈希。源码通过与旧包未更新必须分开说明。

上述输入累计、相同真实时长移动、静止对象更新和缓存逻辑有隔离行为测试支持；竖屏血条有实际源工程预览支持。运行设备帧率和渠道表现仍需针对实际交付验证，不扩展这些证据的结论。

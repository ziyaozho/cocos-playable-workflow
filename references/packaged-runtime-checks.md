# 包体修改与渠道验证

> 执行权限：遵循 [默认由用户测试](../SKILL.md#测试权限默认由用户测试)。下文的测试、验证、运行对比与回归步骤默认交给用户；历史测试记录不是本次授权。未经明确允许，不运行静态校验、编译、隔离测试、浏览器自动化或完整试玩。用户要求导出/压包时，只执行必要交付，不附加测试。

用于用户明确要求修改现有导出文件，或复核渠道扫描结果时。源工程优化仍按[严格体积预算](asset-and-export-checks.md#严格体积预算)执行；不因本参考存在而自动启动完整试玩。

## 启用本流程的授权边界

只读分析现有包体不等于获准修改它。未明确要求构建、导出、压包或修复现有 HTML 时，遵循 [包体权限](../SKILL.md#包体权限未经明确要求不生成最终包体)，默认停在源工程修改与交付说明；不生成候选包，不重封装或覆盖最终文件。此前交付过包体、用户继续报错或要求测试，不自动授权本轮再输出包体。明确的包体授权只覆盖本次约定的对象与操作，不附带测试。

## 修改对象与资源身份

- 确认当前交付文件、最新授权和恢复点。仅包体修改不回写 Cocos 场景、素材或代码，也不重新构建来覆盖用户认可的产物；说明后续从源工程重建不会自动包含这些包体修改。
- 用户移动或重命名包体后，以其最新指定的位置为交付对象；用已知哈希核对文件身份。旧路径缺失时不自动挑选其他历史导出。需要工作副本时先备份目标，写回前检查目标有无并行变化，交付后比对目标文件与已验证副本的哈希。
- 先解出本版本的资源映射和封装入口。用可重复执行的补丁记录资源键、预期匹配次数、修改前后哈希；匹配失败先重新核对版本，不能静默跳过或广泛替换混淆代码。
- 对未授权变更的资源比较解码后有效载荷；允许变更清单与原始导出的差异逐项对应。包装标记、容器格式或压缩算法不同不能替代内容核验。
- 编码载荷包含特殊字符时，检查真实浏览器的 HTML/脚本解析和解码后哈希；文本搜索、JSON 解析或离线解压成功不足以证明浏览器启动正常。
- 重封装后重测最终字节数，并让验证报告绑定同一份文件哈希。后续任何修改都使旧报告不能直接作为新文件的通过证据。
- 按本次变化选择相关复测，不把每个局部改动扩成全量试玩。历史报告可以保留，但要标明其文件和范围，不能只重写哈希冒充新验证；未变有效载荷的一致性也不能代替变更行为的运行检查。

## 压缩与加载

- 按用户画质要求选择有损或无损；对必须保持清晰的 Logo 等资源，转换格式后核对解码像素、透明度、裁切和实际消费者，不以扩展名或质量参数替代检查。
- 加载页与游戏共用同一资源时，先确认是否可共用一份有效载荷，避免早期 Logo 又被完整内嵌一次。不要将某种压缩格式、参数或解码器固定为所有项目方案。
- 记录加载覆盖层、实际场景首帧和输入可用的不同时间。大块解码不能阻止轻量加载提示首次绘制；加载提示应在实际场景绘制后关闭。首屏有品牌或指引不代表玩法已经能接受操作。

## 商店分流与扫描证据

- 根据用户确认的市场 × Android/iOS 配置逐项核对；缺失地址保留待补状态并说明，不猜包名、不把其他地区地址当默认正确值。用户后续重新确认的地址优先于旧的“无效链接”清单。
- 从真实 CTA 消费者追踪到系统识别、地区判定、配置读取及最终 SDK/备用退出入口。核对显式市场、语言/地区、时区的实际优先级，并覆盖 iPadOS 桌面式 UA；不能由一个地区的一次点击推断所有分支。
- 多个 CTA 外观相同不保证出口相同：逐一检查顶部、结束页及遗留点击入口，识别固定商店链接和按平台分流的差异。先遵循用户确认的分流规则，不把看起来正确的一个按钮直接复制到全部平台；共享同一解析入口以减少分支漂移。
- 语言不是地理位置。需要区分同语言的市场时，保留 BCP 47 地区/脚本标签，核对投放配置、地区标签、语言及默认值的优先级；裸语言或未匹配地区的默认市场由用户确认。不要擅自新增 IP/时区定位或外部请求，也不要让商店分流无意覆盖既有 UI 手动语言策略。报告中明确使用的是语言地区推断还是已知投放市场。
- 预期商店目标应来自独立确认的数据，而不只读取被测配置自证正确。共享 Android 地址不能掩盖应区分的 iOS 目标；格式等价与目标 App ID/包名一致分别判断。
- 扫描器命中的注释、压缩库中的 result、胜负关键词或链接字面量只是线索。检查实际执行上下文、场景绑定和入口，不为了静态命中新增伪调用或隐藏真实问题。
- 结算验收区分资源存在、组件受控触发、自然玩法到达。未完整通关不能声称结算流程已跑通；没有失败页时先核对玩法是否存在失败条件，不能单凭缺少某个关键词判错。

## SDK、首触与声音

### 受限沙盒启动

- 目标预览器使用受限 iframe，或报错包含 `srcdoc`、`sandbox`、`SecurityError` 时，先查最早异常。可选 API 的属性读取和存在性判断本身也可能抛异常，例如缺少同源权限时读取 `navigator.serviceWorker`；在该处做局部异常保护，保留其余资源限制。
- 若早期脚本同时负责后续加载器初始化，后续 Promise 未定义可能只是连带错误。确认初始化顺序和状态，避免用默认 Promise 或吞掉后续错误掩盖首个故障。
- 复现目标实际 sandbox 标志，明确是否缺少 `allow-same-origin`；普通顶层页面的通过结果不代表该环境可用。不为绕过错误擅自放宽宿主权限。按授权验证加载提示、真实场景绘制和首次有效输入，并保留正常预览回归。

### 渠道生命周期

- 按当前渠道要求检查 SDK 初始化：区分读取 getState、注册 ready 监听与依赖 SDK 就绪的调用。记录 loading → ready → 可见的实际顺序，以及引擎是否只启动一次；有这些关键词不等于时序已验证。
- 渠道或用户要求首次操作不跳商店时，记录完整的可信按下、拖动、松开/点击过程及 SDK/备用出口调用，同时确认该操作推进玩法。只测 canvas 收到事件或仅测某个 click 回调不够；自动/合成事件也不能代替真实首触证据。
- 若需要首触保护，先写清“首次操作”的定义和重置时机；覆盖首触落在 CTA、首拖推进玩法、后续主动 CTA、横竖屏及事件解绑。一次 pointerdown 计数或合成 Button 事件只能证明局部守卫，不能声称验证了完整可信点击；取消/多指/重复事件也不应误当多次有效操作。MRAID ready 等待与首触限制是两项独立检查，不能用其中一项替代另一项。
- 隐藏或关闭时检查 WebAudio 与媒体元素的实际状态；覆盖隐藏期间新建/重启音频及恢复可见后的行为。不能只检查一个 is_audio 标志，也不要无条件启动原本已暂停的声音。
- 仅包内资源的限制按授权实施，并保留显式 SDK 商店导航。网络守卫和 CSP 要覆盖实际资源路径；若加载器或音频通过 fetch 读取 data/blob，不能用一刀切规则把这些包内请求一起封死。以实际请求记录验证。

## 运行环境与报告

- 真实 AppLovin/MRAID 容器、记录 SDK 调用的浏览器预览、隔离组件测试分开标注。浏览器中用录制替身证明了调用参数，不等于真实广告宿主已验收；仅模拟场景信号也不等于真实首帧。
- 以实际发布包的模块和注册组件为准，不能假设编辑器或源码里的全部 cc 全局导出在发布包都存在。诊断脚本先核对可用 API，不把测试脚本自身的空值当成游戏故障。
- 记录文件哈希、视口、语言、所测分支、事件和必要截图。按本次授权交付已有证据与未覆盖范围；用户接受布局并要求立即导出时，不再扩大视觉或完整玩法测试。

# Cocos 3D 试玩广告工作规则

用于补充项目 `AGENTS.md` 的默认规则。保留现有指令，优先遵循用户和工程中的实际版本、渠道及构建约定。

## 项目约定

- 默认场景为模拟经营类 Cocos 3D 试玩广告，公司提供策划和模型。
- 优先复用旧工程已验证的人物、收集、堆叠组件、预制体及 2D CTA。
- 默认使用 SuperHTML 构建 AppLovin 文件，最终小于 5 MB。保持已有体积统计口径；没有口径时明确报告字节数和换算方式，不利用换算差异宣称达标。

## 修改范围与恢复点

- 修改代码、资源或复盘文档前检查 Git 状态并建立本地恢复点，不推送。
- 保留用户已有改动，区分已有改动和本次改动。不要提交凭证、缓存、无关大文件或忽略文件；没有可提交变更时记录当前提交即可。
- 非 Git 工程先说明缺少恢复能力，不冒充已备份。
- 列出本次修改文件及必要性，只修改当前任务所需内容。确需扩大约定范围时说明影响并等用户确认。
- 从工程配置确认 Cocos 版本，核对该版本 API，不顺便重构、改名或清理功能。

## 策划与阶段状态

- 完整策划保存为 `docs/playable-spec.md`，保留原始要求，区分待确认内容。
- 阶段方案和验收标准保存为 `docs/implementation-plan.md`，状态为未开始、实现中、待用户验收或已通过。
- 每阶段读取相关要求；不只依赖聊天摘要。用户指定阶段前，不擅自实现完整关卡。
- 实现前列出本阶段完整行为、复用组件、节点路径、BDD 用例及验收条件。
- 每次输出代码前，先输出 BDD 用例，再以注释写入代码，最后基于用例实现。
- 实现后逐项检查功能覆盖情况，不能只报告改动文件。未实现要求明确列出。

## 场景、模型和动画

- 核对节点实际层级和唯一身份，不根据同名节点猜绑定。
- 修改场景或预制体时保留有效 UUID、资源引用和已有绑定。
- 复用已调好的人物预制体与动画。未确认的新模型动作范围不得猜测；帧范围须同时明确采样率和边界约定。
- 模型贴图导入故障先收集完整报错、格式和引用信息；3D 查看器能打开仅是线索，不证明 Cocos 导入配置正确。
- 保留源资产及可恢复版本，不擅自重新生成贴图来掩盖导入或引用问题。

## Bug 诊断

- 整理预期、实际、最短复现、发生轮次、相关日志和最近改动。
- 对照历史经验检查条件；有证据才确认原因。必要时先加可开关诊断日志，由用户运行复现。
- 日志只在状态切换和异常时输出，避免逐帧刷屏。按问题记录顾客编号、批次、生命周期、队列索引、移动根节点与模型节点位置、动画状态，以及生成、结账、离开、隐藏、销毁或回收事件。
- 最小修复后检查相邻流程。失败时重新核对原因，不继续叠加猜测性补丁。回滚仅针对明确属于本次的修改，保留其他改动。
- 默认用户手动验收；未经同意不启动自动浏览器预览或大范围 UI 测试。可以执行已有编译与针对性静态检查。

## 验收交付

- 每阶段提供操作步骤、预期结果、必要重复次数，以及受影响旧功能的回归项。
- 顾客功能连续检查至少三批，覆盖生成、排队、补位、结账、离开和下一批衔接；根据实际策划调整具体行为。
- 人物功能检查移动与停止、动画切换，以及相关生命周期后的恢复。
- 逐项说明实现位置、执行过的检查、未验证内容和未完成事项。编译成功不得表述为运行已通过。
- 用户确认后更新阶段状态；修复有效后记录有价值的经验。

## 压包

- 分析构建资源体积，优先处理最大资源，在 Cocos 工程中优化后重新构建。
- 不直接改写最终 AppLovin 文件中的 Base64，不破坏 SuperHTML 包装和渠道接口。
- 模型、贴图、音频允许有损压缩，但不得出现明显视觉差异；删除前核对静态及动态引用。
- 记录最终文件优化前后大小和主要改动。默认关闭诊断日志。
- 构建达标后仍由用户运行最终文件，确认加载、画面、动画、声音、玩法和 CTA。

## 经验与复盘

- `docs/development-lessons.md` 保存：问题表现、适用版本及结构、已确认原因与证据、无效尝试、有效修复、预防检查和验证方式。
- 未证实原因标为待验证，不提升为通用规则。
- 同类问题重现，检查是经验未读取、检查缺失、检查未执行还是条件变化，并修正相应预防动作。
- 用户明确确认项目完成或交付通过后，无需再次请求复盘许可，更新 `docs/project-retrospective.md`，记录耗时环节、重复错误、无效判断和有效方法。
- 依据已确认经验优化当前项目 `AGENTS.md`：合并重复项，修正过时内容，只保留跨项目适用规则。每条规则写清执行时机、具体动作和通过条件。
- 项目专属节点和动画帧范围留在资产或项目说明。无新证据时，不为复盘强行新增规则。
- 报告规则更新依据及下一项目需沿用的文档。不擅自更新全局技能或其他项目；新项目通过携带最新文档继承经验。

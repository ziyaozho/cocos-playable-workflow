# 跨项目共享经验

> 执行权限：遵循 [默认由用户测试](../SKILL.md#测试权限默认由用户测试)。下文的测试、验证、运行对比与回归步骤默认交给用户；历史测试记录不是本次授权。未经明确允许，不运行静态校验、编译、隔离测试、浏览器自动化或完整试玩。用户要求导出/压包时，只执行必要交付，不附加测试。

按任务读取相关条目；共享技能维护须有用户明确授权。只保存已验证、去除公司及项目细节、具有适用条件的经验，不用篇幅代替学习质量。

## 已确认经验（2026-10-08）

来自一次用户明确确认完成的 Cocos Creator 3.8.8 试玩制作。证据分为导入/导出检查、隔离测试及用户确认；没有把完整游戏自动运行列为已执行检查。

### 新模型继承旧导入简化参数可造成实际画面变形

- 适用条件：复制人物 GLB 的 .meta 或沿用旧模型导入设置。
- 证据：转换源与离线姿态正常，但实际导入面数约剩一成，出现脸部与四肢形状破坏；关闭新模型的网格简化后用户确认正常。
- 预防：导入前查 meshSimplify 与相关有损设置，导入后比较实际面数与预期值。不能仅凭截图认定原生骨骼损坏。
- 通过条件：导入拓扑与绑定符合预期，Creator 画面由实际运行或用户确认验证。

### 动画文件有关键帧不等于导入时长有效

- 适用条件：自行生成或重写 glTF/GLB 动画访问器。
- 证据：时间 SCALAR 访问器遗漏 min/max 后，导入截取终点被写为零；恢复实际时间范围并重新导入修正。
- 预防：检查采样时间、时间范围和片段名称，导入后读取片段时长；不能只检查关键帧数量。
- 通过条件：动作时长大于零且符合源动作，绑定路径可解析，实际动作切换仍单独验收。

### 导入资源根节点不一定是真正的门板或挂点

- 适用条件：复用双开门逻辑，或调整运行时重新排列的背包堆叠物。
- 证据：门板在具有额外变换的子节点中，驱动该网格并保持世界变换完成复用；统一移动背包父节点可保留子挂点重新排列后的偏移。
- 预防：追踪真实渲染节点、旋转轴、共同父节点和运行时位置写入；保留业务绑定，不只按节点名称或截图猜方向。
- 通过条件：世界位置/旋转/尺寸不意外改变；双向门逻辑、堆叠重排与用户画面确认分别记录。

### 最大贴图优先优化可避免人物删面

- 适用条件：单文件试玩包超出严格体积上限，实际内嵌图片占主要体积。
- 证据：缩小并量化两张最大人物贴图后，正式构建达标；模型与动画的二进制有效载荷保持不变。
- 预防：先读 ZIP 与资源映射的体积排名，保留原图和原包，保留 UUID；尺寸和颜色数按本项目画质授权选择。
- 通过条件：正式重新导出满足字节上限，CRC/图片解码/关键资源有效载荷核对通过；画质由用户运行验收。

### SuperHTML 可能保留声明容器却省略初始化脚本

- 适用条件：声明由网页自定义内联脚本初始化并经 SuperHTML 包装。
- 证据：首次实际导出出现底部背景但无文字，最终 HTML 不包含初始化代码；在构建包装后自动补入初始化脚本后，实际导出的声明部分通过多语言和横竖屏隔离测试。
- 预防：在实际最终 HTML 中确认初始化代码及显示文本，不以 DOM/CSS 存在或构建前测试作为已显示的证据。先核对具体版本，不假设每个包装器都会丢脚本。
- 通过条件：下一次构建仍自动包含脚本；透明覆盖不缩小游戏视口，独立区域不与视口相交；两种模式都保留语言切换、安全区与输入穿透。

### 场景序列化与并行编辑需要语义比较

- 适用条件：Creator 打开时外部修改场景、存在未保存节点或用户继续编辑。
- 证据：保存后才可绑定新摆放的门；Creator 重排对象 ID，同时用户修改地面高度和材质，按旧数组下标比较会误报。
- 预防：截图/磁盘不一致时先确认保存，按稳定节点身份和引用映射比较；只修改本任务字段，不把并行编辑视为待回滚内容。
- 通过条件：既有节点和资源绑定保留，任务新增/变化字段明确，用户后续编辑未被旧快照覆盖。

## 本次关卡主题替换的已确认经验（2026-10-08）

证据包含场景/模型与动画检查、隔离行为测试、Creator 编译导入、正式导出核对及用户确认关卡设计完成；未把完整游戏自动运行记为已验证。

### 放大模型后要检查完整升级状态

- 适用条件：收集物放大、升级显示更多节点，或出现动画改变父级缩放。
- 证据：原尺寸的中心偏移和间距在升级后造成围栏、地面及相邻模型穿插；重新居中排列并按动画峰值检查边界后，用户确认通过。
- 预防：用实际模型范围、父级变换、全部显示节点和最大动画缩放计算间隔及地面/围栏净空；拾取位置随视觉位置对应移动，保留尺寸与业务数量。
- 通过条件：峰值与稳定状态的完整模型范围无穿插，升级后实际画面另行核对。

### UI 的实际显示层与模型轮廓必须分别追踪

- 适用条件：主题 UI 替换、进度填充，或将 3D UI 素材改为 2D Sprite。
- 证据：替换同名图标后底图/填充图仍显示旧图案；源贴图四角不透明，原网格承担外圈裁切。处理实际显示层、按几何生成透明资源后，导入数据和用户反馈确认修正。
- 预防：追踪实际显示与状态切换的全部层；区分图案、货币、价格和进度；检查像素 alpha、图集 UV 和轮廓方向，不凭文件格式判断透明。
- 通过条件：目标状态使用新图案，非目标区域和金额逻辑保留；透明资源导入后角部 alpha 正确。

### 地面产物与传送物可以使用不同模板

- 适用条件：同一生产方法同时生成地面物品和传送物，但用户要求不同外观。
- 证据：沿用同一模板会让两处一起改变；可选传送外观模板区分两处，已隔离测试有配置、空配置和传送未激活三种行为。
- 预防：画清当前生成/搬运映射，保留默认回退，不改变消耗、时间、数量或销售绑定。
- 通过条件：两处分别显示指定外观，默认与未激活路径保持原行为；完整游戏仍单独验收。

### Canvas 声明需同时检查有效文字尺寸、避让和内嵌资源

- 适用条件：多语言 PNG/SVG 声明存在大面积透明画布，项目已有原生 UI 和语言管理。
- 证据：声明使用实际文字矩形适配，覆盖语言回退、横竖屏和安全区隔离场景；正式包解码及 CRC 检查确认组件与所有语言图片存在。后续用户截图证实，短单行声明按统一宽高上限放大后，仍可在屏幕内遮挡移动引导；此前尺寸与资源检查没有覆盖这一点。缩小后的各语言尺寸回归和正式导出已检查，实际游戏避让效果尚未获用户验收。
- 预防：保留原文和样式，用有效文字边界、目标可读大小、语言行数和一致安全区单位布局；可用宽度只作限制，不强行填满。检查声明与实际引导文字和操作区的显示范围及间距，避免用不可读的字号通过测试。详细步骤见[声明与多语言布局](asset-and-export-checks.md#声明与多语言布局)；接替旧声明避免重复，保持视口与输入，核对最终内嵌资源表。
- 通过条件：各语言可读、等比、不溢出，显示引导时文字范围不交叠且有间距；资源导入与最终导出完整。隔离布局、导出核对和实际设备画面分别记录，不把一次修复尺寸提升为跨项目固定值。

## 包体与引导的已验证经验（2026-10-20）

### 包体修改应有自己的恢复点和验收对象

- 观察：用户在优化过程中将范围改为只修现有 HTML；可重复封装和解码后资源哈希核对，使后续链接、音频和局部玩法补丁可以保留已认可的素材与交付名称。
- 后续检查：先确认修改对象；报告绑定实际交付哈希，对未授权变更的有效载荷做一致性检查。源码构建通过与包体重新封装通过分别记录，细节见[包体修改与渠道验证](packaged-runtime-checks.md)。

### 指引可见、动画播放与输入有效是三个检查项

- 观察：原拖动动画仍在循环，但父节点被隐藏，只剩文字；同时开场镜头锁定输入，首帧收到拖动却没有角色位移。
- 有效处理：恢复原演示的可见层级，并按获准的首屏要求消除输入锁定；真实首拖验证位移和引导隐藏。英文横竖屏实际预览与用户认可支持这些结论，不能扩称其他语言或完整通关都已验证。

### 固定锚点和引导分组必须一起进入验收条件

- 观察：恢复动画后，声明和摇杆仍然重叠；把声明插入摇杆与文案中间也未符合用户预期。
- 有效处理：根据用户最终要求固定声明，仅将摇杆和文案作为一组放在其上方，用实际声明高度和字形范围验收首次拖动前后的位置。只有用户固定锚点时才采用该约束，不复制本项目间距或设为全局默认。

### 渠道扫描的静态命中不能代替运行记录

- 观察：注释中的 SDK 调用、压缩库的 result 变量和商店地址字面量，都曾作为扫描证据；这些片段不能证明首触、结算或分流已正确执行。
- 后续检查：独立确认目标地址，逐地区/系统记录实际消费者到出口的分支；首触、原生音频和 ready 需要各自的运行证据。已验证的浏览器 SDK 录制不提升为真实 AppLovin 容器或自然通关验收。

### 可选 API 的 getter 异常会中断共享启动脚本

- 观察：在仅允许脚本、未授予同源权限的 `srcdoc` 沙盒中，读取 Service Worker 属性直接抛出异常；同一脚本后续的加载 Logo 初始化未执行，继而出现 Promise 未定义。普通顶层预览没有复现该限制。
- 有效处理：在可选 API 访问处局部保护，保留资源封闭规则；相同限制下的横竖屏真实场景和首次拖动验证通过。浏览器沙盒记录不能提升为真实广告宿主验收。检查方法见[包体修改与渠道验证](packaged-runtime-checks.md#受限沙盒启动)。

### 本地化图片和本地化文字是不同消费链

- 观察：中文 Logo、按钮图片和声明已正常显示，但移动提示仍回退英文，地面标识也没有文字语言绑定；语言表实际缺少两套中文字典，地区和脚本标签识别也未覆盖所需繁体场景。
- 有效处理：补齐范围内的简繁文字并接入既有 I18N 事件，保持场景节点、位置和其他语言。中文新页面、横竖屏及可见文字切换已实测；隐藏节点的验收时机是它实际显示时。不要只用图片语言或静态键存在判断文案完成，见[缩放与多语言文字](asset-and-export-checks.md#缩放与多语言文字)。

## 渲染、交付与分流的隔离验证经验（2026-10-26）

- 画面模糊：最终画布已适配 DPR，但中间纹理仍偏低；提高中间尺寸时又遇到引擎逐边限制。用统一缩放约束并检查真实尺寸可保留比例。方法见[画面模糊与局部发黑](asset-and-export-checks.md#画面模糊与局部发黑)，不推广某个版本的固定像素上限。
- 桌面穿模与裙摆条纹：实际包内网格边界揭示物体原点和底部不一致；基础人物在不同灯光下看似正常，复用实际光源参数后才复现条纹，目标渲染器阴影接收对比消除了该隔离症状。模型、动画和材质未重做。此证据支持局部修复，不等于完整试玩或真机画面已验收。
- 商店出口：顶部固定 App Store 与结束页按平台分流曾产生不同地址；应先确认市场规则，再统一解析入口。独立地址表、实际包内组件与按钮事件记录能验证调用参数；语言标签推断、合成首触、本机 MRAID 替身都不能提升为真实地区或广告容器验收。方法见[商店分流与扫描证据](packaged-runtime-checks.md#商店分流与扫描证据)。

## 新经验记录字段

- 问题表现与适用条件：引擎版本或相关结构条件。
- 已确认原因与证据：区分用户验收、实际检查和未验证推测。
- 无效尝试与限制：为什么无效，条件变化时是否需要重新判断。
- 有效修复原则：不包含公司源代码、素材或特定项目配置。
- 预防动作：什么任务开始前执行什么检查。
- 通过条件与验证方法：明确可观察行为及必要重复次数。
- 重复发生时：检查经验是否读取、检查是否执行以及条件是否变化。

记录实际经验后移除不再适用的“暂无经验”说明，保留字段规范。

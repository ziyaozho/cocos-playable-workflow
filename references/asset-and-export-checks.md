# 资源与导出专项检查

> 测试与预览：遵循 [技能入口的规则](../SKILL.md#测试与预览通常由-ai-执行)。用户不着急且未限制测试时，AI 选择与当前任务相称的测试与预览；用户接手或限制范围时立即遵从。历史记录不等于本次测试结果，最终包体仍需单独授权。

按当前任务读取相关段落。项目节点、UUID、动作帧范围、偏移值与语言配置留在项目文档，不复制到共享技能。

## 人物换皮与动画

- 确认绝对工程路径、package.json 身份与实际场景；同名工程和同名场景不能作为替代目标。

- 模型、原生骨架、权重和绑定姿态一起检查。骨骼数量不同不等于骨架损坏；没有自带动作也不等于没有骨骼。选择保留原生骨架或适配旧骨架时，说明动作路径与挂点的兼容条件。

- 核对位置单位、根缩放、轴向、逆绑定矩阵、渲染节点和动画根。改变骨长时同时检查网格局部偏移的单位，不复制其他工程的固定倍率。

- 新模型 .meta 只继承所需关联和配置；检查 meshSimplify、meshCompress、LOD 与量化，不把旧人物的有损参数直接应用到新体型。

- 生成 glTF 动作时保留时间访问器实际 min/max、采样率、通道、片段名称与范围。Creator 导入后核对面数、片段时长和挂点引用，再做移动/停止/工具动作验收。

- 离线姿态图与源 GLB 的合法性只是前置证据；实际导入和最终构建产物必须另外检查。

- 用户要求“替换人物，注意动作”时，先列旧状态到新片段的映射，核对自动播放、默认站立、循环、过渡、移动/停止和任务相关工具动作。保留业务组件、根变换、挂点、触发时机与生命周期恢复；需要适配层时只接显示与动作，不重写玩法。方向状态代码存在不代表对应片段已绑定，必须检查实际动画资源和采样结果。

## 材质绑定与导入闭环

- 从实际场景或运行时实例的渲染器出发，追踪 mesh/子资源、材质 UUID、effect、贴图属性与 define，再查源资源及导入结果。同名 FBX/材质要按路径与 UUID 区分；运行时代码覆盖材质时同步查赋值入口。

- FBX `imageMetas.remap` 只负责导入贴图映射，不能证明外部材质已经绑定该图。核对实际材质的属性槽及对应贴图开关，按当前 effect/schema 使用名称，不盲填另一版本的 `mainTexture`、`albedoMap` 或 `USE_ALBEDO_MAP`。

- 修改源资产和必要 .meta 后等待 Creator 完成导入，再检查实际生成的材质/纹理引用与像素；不手改 library 充当持久修复，不默认清空整个缓存。复制材质时带齐 effect、贴图及必要元数据，保留非目标消费者。

- 静态引用闭环、导入完成和实际画面分别记录。若只给编辑器操作步骤，列出已确认的资源路径、资源类型、Inspector 开关及拖入槽位，并明确尚未执行修复或视觉验收。

## 画面模糊与局部发黑

- 画面模糊时分别核对 CSS 显示尺寸、最终画布像素、中间 RenderTexture 尺寸与源贴图。只提高最终画布 DPR，不能补回低分辨率中间纹理丢失的细节。先定位实际瓶颈，不直接重采样所有贴图。

- 调整渲染分辨率时查当前引擎版本和真实 API 的尺寸限制；宽高共用一个缩放因子，避免逐边截断造成拉伸。测试实际返回尺寸、横竖屏、DPR 变化及禁用/重启；保持逻辑视口、相机取景和输入映射。像素增加意味着渲染成本增加，隔离软件渲染不提供真机帧率保证。

- 局部发黑或条纹先区分颜色贴图、法线/PBR、重叠几何、骨骼形变和阴影。以实际游戏预制体的材质覆盖、动画状态、光源位置及阴影参数建立同条件对比；基础模型或不同灯光下没有条纹，不代表游戏问题消失。

- 每次只改变一个候选因素；阴影条纹已复现并被消除后，才选择偏移、阴影范围或仅目标渲染器接收设置等最小修复。关闭阴影接收会失去外部阴影，不作为人物通用默认，也不因此重绘贴图或全局提亮。核对当前引擎属性的枚举/布尔类型，测试替身也应模拟其限制。

## 资源迁移与模型切分

- 从场景渲染器与导入子资源追踪真实来源；道路、地板或装饰可能属于同一个 GLB。

- 区分内嵌与外部贴图/材质/缓冲区，连同所需 .meta 和目录元数据复制；查目标工程中的 UUID 冲突，避免覆盖。

- 用户只要把素材放入资源管理器时，保持场景不变；报告实际导入状态，文件复制完成不等于已经在编辑器可见。

- 切分模型按用户指定方向执行；未指定且无明确几何线索时，可保留源模型、沿合理边界生成两半，说明选择。跨切面三角形要真实裁剪和插值，保留 UV/法线/材质；必要时处理切面封口，不把所有地形都当实心物体。

## 主题与产物替换

- 先确认用户最终要求的映射。地面产物、传送带、背包和顾客图标可以使用不同素材，不能按旧资源名作全局替换。

- 追踪实际生成、搬运和传送调用。若同一模板同时生成地面物品和传送物，而用户要求两者外观不同，优先增加可选外观模板；空配置保持原行为，不改产量、消耗、时间或销售规则。

- 节点改名限于用户要求的范围，保留稳定身份和序列化引用；核对 getChildByName、字符串分支、动画 HierarchyPath。共享动画仍被其他未修改实例使用时，另存适用副本，保留动作名称与时长。

## 动画驱动摆放与完整布局

- 检查位置、旋转和缩放由哪些关键帧或运行时代码写入。只改 Inspector 而未处理覆盖来源，不能保证运行时保持该值；需要偏移时同步适用动画或调整不被写入的渲染子节点。

- 使用模型实际顶点或包围范围、完整父级变换和动画最大缩放检查摆放。覆盖初始可见、升级全部显示、出现动画峰值及稳定状态，不只看编辑器静止画面或物体原点。

- 模型放大后重新按实际尺寸计算中心偏移；检查相邻间隔、地面、围栏、通道和传送带边界。保持用户确认的尺寸，必要时重新排列，但不要更改业务数量。

- 移动收集位置时让拾取点和视觉模型保持对应；保留编号、补充、飞行和回收引用。输出对应层级、位置与实际边界检查范围。

### 堆叠物穿模与飞行目标

- 先确定出问题的是桌面、背包、顾客手持还是地面模板。用同一坐标系下的实际网格底部与支撑面高度求差，包含渲染子节点偏移、旋转、父级缩放及出现动画；原点在桌面上不等于物体没有穿模。优先调整目标容器，保留共享模板和其他消费者。

- 首次交付飞向远处时，同时追踪队列进度、节点真实位置、目标挂点及事件顺序。初始化只设置逻辑进度，或到达判断在位置更新前提前返回，都可能向旧位置交货。隔离用例覆盖普通到达、长帧越过目标、事件触发时的位置、排队间距、单次交付和离场复用，不通过改花束飞行轨迹掩盖顾客位置错误。

## 实际 UI 显示与透明轮廓

- 从截图追踪真正显示的 Sprite、SpriteRenderer、MeshRenderer 及状态切换。底图、填充图、升级前后图和隐藏模板可能同时存在；不能因名为“图标”的节点已替换就宣布完成。

- 只换图案时保留金额、货币图标、底板、填充范围和动画。若图案与这些内容合并在同一素材，选择独立节点、覆盖或局部材质替换；不要默认替换整块面板或把素材上的固定价格写入玩法。

- 局部材质替换依赖原归一化 UV 时，核对动态/自动图集是否改变 UV；必要时只对该资源副本禁用打包，不影响其他图片。

- 检查 RGBA 像素、alpha 范围与实际导入数据；PNG 扩展名或透明旗标不能证明背景透明。原模型可能靠几何轮廓裁去贴图外圈，直接改成矩形 Sprite 会露出底色。

- 将依赖模型轮廓的 UI 改为 2D 时，可按原网格渲染透明图，或使用明确适用的裁切方式；保留图案，检查气泡尖角方向、描边、中心与四角 alpha，以及导入后纹理格式。

### 缩放与多语言文字

- 放大前确认目标是图片本身、含按钮的父节点，还是图标、底框、金额组成的整组。只改获准的方向与消费者；检查布局和动画是否覆盖缩放、嵌套控件是否一起变化，以及旋转回来是否累计放大。尺寸调整不默认重采样或有损处理原图。

- 测量实际图片或字形边界，核对边界 API 是否把子控件并入父节点范围；不要由包含按钮的联合边界误判 Logo 与按钮重叠。跨运行比较用语义路径、消费者和 Transform，不把自动生成的运行时节点编号当作稳定身份。

- 图片已本地化不代表文案已本地化。对任务涉及的引导、按钮文字和世界空间标识，追踪系统/手动语言识别 → JSON 字典 → 回退语言 → Label/I18N 绑定 → 后续脚本写入；保留既有语言框架，避免全局替换英文常量误改其他语言或逻辑标识。

- 简繁中文均在范围内时，按项目规则核对地区与脚本标签的映射及各自字典，不由中文 Logo 推断使用了哪套文字。验证语言首次进入、横竖屏和当前可见文字切换；隐藏节点在随后显示时验收当前语言，不因隐藏旧值误判失败，也不能因此漏掉其启用后的刷新。

- 核对实际中文字符的字体回退、字形大小、换行与裁切；英文可读尺寸不证明中文同样完整。地面文字仍保留原节点、触发区、摆放和业务绑定，回归本次未要求改变的语言。

## 复用参考逻辑与统一偏移

- 先阅读参考脚本、调用者、序列化组件与目标工程已有 API。只迁移所需行为及依赖，缺失接口做最小适配，不导入整套无关玩法。

- 门逻辑区分两扇门与两组门；根据真实门板中心与外侧轴计算触发、旋转和阻挡，保留用户摆放的世界变换。

- 堆叠物后移先查运行时位置写入。若子挂点会被重新排列，调整对应共同父节点而不是逐个改物品；只移动用户要求的挂点体系，避免影响载具或其他角色。

## 批量 UI 与单文件预算

- “所有 UI”“包括这些”等范围先列完整目标清单，记录源文件、显示消费者/状态、尺寸、字节数、是否共享及替换状态；截图示例不能充当全部范围。区分实际 UI、非 UI 贴图和无引用资源，范围不明时先推进明确部分并标明待确认项。

- 逐项核对目标图、填充图、升级态、隐藏模板及运行时加载资源，保留原文、价格、数量、图标业务绑定与必要 alpha。完成清单中的子集时报告完成数、总数及剩余项，不以若干成功样例宣布全部完成。

- 区分每文件上限和整个包上限，记录严格小于或不超过的边界；KB/KiB 未约定时说明所用口径。逐一读取最终文件实际字节，不能用平均值或仅源图尺寸证明合规。源文件、导入后的纹理和最终包内资源大小分别标注，按用户约定对象验收。

- 资源重新导入后核对实际像素、透明度、引用和显示状态；若交付范围含导出，再核对最终包确实使用该批资源。按当前范围检查相邻 UI，避免共享资源替换改变非目标画面。

## 启动性能与就绪状态

运行掉帧、输入迟滞与测试条件的区别见[运行性能与输入适配](performance-and-input.md)。

- 先定义用户要求的指标：HTML/加载覆盖层首次显示、真实场景首帧、实际输入可用。记录设备、浏览器、冷/热缓存、网络条件及计时起点，不把覆盖层出现称为游戏已就绪。

- 对同一构建入口和测试条件比较修改前后结果；用真实场景呈现与输入响应事件确认就绪，不能用定时器或资源下载完成代替。只测到首屏时只报告首屏数据。

- 解码/解压和包装优化须保留实际有效载荷、启动顺序及渠道接口；是否使用 ASM.js/WASM 按当前插件版本、构建配置和渠道要求核对。SuperHTML 5.3 的 WASM 限制见[构建设置与旧包排查](#superhtml-构建设置与旧包排查)，不推广为所有 Cocos 项目的强制值。

- 加载层按实际就绪信号移除，并检查语言、透明/输入处理和失败状态；测试沿用当前授权范围。最终仍核对本次正式交付的文件名、字节和资源完整性。

- 首屏显示移动提示时，用真实首次拖动检查角色位移或预期玩法推进；开场镜头可能仍锁住输入，不能把提示文字出现或 canvas 收到事件当作可操作。未经授权不据此改开场设计。

## SuperHTML 构建设置与旧包排查

- 先核对实际安装的插件版本与构建日志。SuperHTML 5.3.0 会拒绝含 `.wasm` 的构建输出；日志出现 `Wasm files are not supported` 并要求使用 AsmJS 时，在支持该选项的 Creator 构建面板将“原生代码打包模式 / Native Code Bundle Mode”设为 **AsmJS**，序列化值为 `"nativeCodeBundleMode": "asmjs"`。`both` 仍会生成 WASM，不能代替 `asmjs`；其他插件版本或渠道按实际支持能力处理。

- 修改实际执行的 Web Mobile 或 Web Desktop 任务。Creator 3.x 的已保存任务可位于 `profiles/v2/packages/builder.json` 的 `BuildTaskManager.taskMap.<taskId>.options.nativeCodeBundleMode`；若项目用 `common.nativeCodeBundleMode` 作为新任务默认值，同步该值。任务 ID、平台、输入和输出目录以当前日志为准，不批量改其他任务。独立构建 JSON 只有在实际命令读取它时才生效，不能代替面板已保存任务的设置；保留场景、UUID、渠道和其他构建参数。

- 修改前保存实际任务配置的本地恢复点；`profiles` 可能被 Git 忽略，应单独保存需要修改的配置副本，不强行纳入整份本机配置。Creator 已打开时，磁盘修改不代表内存中的面板选项已更新；重新载入配置并核对面板显示，留意编辑器保存旧值覆盖磁盘修改。

- WASM 可能来自 Spine、Bullet 等运行依赖，不因插件报错删除业务必需模块，也不靠手工删除输出中的单个 `.wasm` 文件绕过。下次获准构建时优先使用新的 Web 输出名称或目录，避免旧 WASM 混入本次打包；不因此自动清空缓存或删除已有 HTML。

- 分开读取 Creator Web 构建和 SuperHTML 打包结果。即使 Creator 显示 `build success`、插件钩子显示完成或日志以 `-- end --` 结束，插件内部仍可能报错且不更新 HTML。结合本次 `s_input_dir`、`s_out_dir`、实际生成路径和文件时间定位来源；已有 HTML 的时间早于本次构建，且本次插件报错时，应识别为旧产物残留，不能将其当作新包。文件存在、文件名相同或体积变化，均不能单独证明成功导出或发生覆盖。

- 获准导出后，记录本次插件生成结果、最终 HTML 路径、更新时间和实际字节数；需要确认是否被后处理覆盖时再追踪复制/重封装调用和文件身份。配置改为 AsmJS 只证明设置已修改；本次导出成功和实际运行验收分别取证，未构建时明确旧包尚未更新。

- 修复设置或更新技能不自动授权构建或改写现有 HTML；测试和预览遵循技能入口及用户当前指令。

## 严格体积预算

- 确认渠道和当前真实输出；用户重命名交付文件时保留名称。未另约定时，5 MB 以下按严格小于 5,000,000 字节执行。

- 保存源码 Git 恢复点及原图、原导出；统计 ZIP 条目和资源映射，优先处理实际打包的最大资源。

- 按授权选择无损或有损。不要用低比例人物删面替代贴图优化；维持骨架、蒙皮、三角索引、动画、材质引用与动态依赖。

- 默认从源工程优化；用户明确要求构建/导出时才执行正式构建，并默认关闭诊断日志。用户限定仅改现有包体时，遵循[包体修改与渠道验证](packaged-runtime-checks.md)并说明源工程未同步；构建或重新封装成功均不代替渠道运行验收。

- 外层 ZIP 做解码/CRC 检查，内嵌图片可解码；按具体包装规则比较二进制有效载荷。含编码标记的 data URL 不能当标准 Base64 直接比较，也不应因随机包装标记变化判定模型已改变。

- 比较实际字节数和关键资源保留情况。未运行完整包时如实报告，不因隔离检查通过宣称 CTA 或完整玩法通过。

## 声明与多语言布局

- 读取用户提供的原文和当前 I18N 自动/手动语言规则；不要从别的工程复制语言回退策略。

- 先识别项目声明位于 Cocos Canvas 还是 HTML。优先复用现有语言事件、SpriteFrame 或 Label；不要为已有原生 UI 默认增加另一套网页语言系统。接替旧声明时避免重复显示。

### 尺寸与避让

- 声明图片的整张画布可能大部分透明，按有效文字边界配置显示矩形，保留原图、透明和描边；SVG 转资源后检查原文和实际字形。裁切 PNG 优先保留原调色板及透明信息，避免无必要转 RGBA 增大包体；无损操作按解码像素核对，文件大小不证明画面一致。

- 先确定声明文字的目标可读大小、行数和放大上限，再依据可用宽高等比缩放。可用宽度是约束，不是必须填满的目标；短单行、小尺寸或不同语言素材不能统一撑满屏幕或共用很高的块高度。按实际字形与行数选各语言尺寸，不能为通过边界检查把多行正文缩到不可读；具体参数留在项目，不套用一次修复的数值。

- 在声明与引导同时可见的状态中，定位实际引导文字、下载按钮、摇杆和底部操作区；按需要检查启动引导、后续提示和结束界面。将声明有效文字范围与这些 UI 的实际显示范围投影到同一坐标系，检查交叠和必要间距，不能只验证声明落在屏幕内。Label 空白布局框不等于字形边界；判断字形范围时包含描边、换行和父级缩放。

- 先按用户最新要求确定固定元素、允许移动的元素及必须成组的元素。固定声明时保持其安全区锚点，让引导组根据声明实际高度定位；相邻元素不要互相追随形成循环避让。检查引导出现、首次拖动、引导隐藏和结束页前后的固定元素位置。

- 缺少动态引导时，先检查原动画、轨道路径、祖先节点 activeInHierarchy 和真实输入绑定；动画在播放不代表画面可见。保留已有演示并适配位置，按实际输入隐藏演示，不为避重叠只剩静态文案，也不让演示拦截真实摇杆。

- 优先缩小声明的过量放大、按语言调整尺寸及利用现有底部空白，保留引导和操作区的原位置、样式及业务绑定。空间不足且继续缩小会不可读时，说明冲突并提出需预留独立区域或调整布局的具体方案；未经用户授权不隐藏声明、删除原文、移动引导或缩小游戏视口。

- 同时检查 Canvas/父节点缩放、相机投影、Widget、屏幕变化事件和安全区的坐标单位。区分 CSS 像素、设备像素与 Cocos 设计单位，宽高、间距和安全区须一致换算；在语言或窗口变化且 UI 布局完成后重新检查尺寸与避让。声明不拦截输入，注册的事件在禁用时成对解绑。

- 透明覆盖模式保留原游戏视口，无背景、输入穿透；独立区域模式按声明换行和安全区预留空间。两种模式都需检查与游戏 UI 的关系。用户改模式或要求所有语言避让时，更新最终验收条件及测试覆盖，不继续执行旧的相冲突约束。

### 导入与正式导出

- 声明初始化要进入真实最终导出。网页内联脚本可能被某条 SuperHTML 路径省略；先检查导出，再选可重复执行的构建钩子补入代码，不依赖手工改一次性的输出。

- 检查启动顺序：容器存在后初始化、引擎启动前确定必要视口模式，手动语言变化与窗口旋转能更新。事件监听解绑使用已绑定的实例，不在场景销毁时重新查询单例。

- 按声明实现选择导出核对：HTML 方案查实际 DOM、样式和初始化代码；Canvas 方案解码最终内嵌 ZIP 及其中的资源表，查场景/组件代码、所有语言图片及资源引用，不能仅搜索 HTML 文本或 ZIP 文件名。包装器可能将图片放入资源表并在 data URL 插入编码标记，按本版本加载逻辑还原后核对图片有效载荷。

- 按已确认的源工程或仅包体方式交付尺寸修改，保留修改前产物，更新用户指定名称的交付文件；核对它确实对应本次修改，并报告实际字节数。

### 验收与证据

- 实现前 BDD 至少覆盖：短单行与长多行语言、语言回退及切换、窄屏和横竖屏、安全区、声明与引导同时显示、输入穿透。尺寸上限测试之外，还要检查实际显示范围不交叠、间距足够和正文可读；回归用例应能暴露修改前的过量放大或遮挡。

- 用户截图可以证明原问题；按固定尺寸计算或合成示意图只证明对应假设。隔离测试通过、Creator 导入成功、资源存在和 ZIP CRC 通过，都不能证明最终游戏中声明不遮挡引导。按任务范围检查实际画面，未运行的部分明确标为待验收；用户接手或限制时遵从其指令。

## 完整 Cocos 工程 ZIP 交付

- “完整包体”可能指 Creator 源工程 ZIP、网页构建 ZIP 或渠道单文件 HTML；上下文不足时先澄清，期间可只读核对。源工程归档不自动授权重新构建或同步 HTML 专用补丁。
- 按当前磁盘快照归档，保留用户既有改动；包含 package.json、tsconfig.json、全部 assets 与 .meta、settings、所需项目扩展及其已安装依赖、实际使用的资产模板。不要一概排除扩展内 node_modules。library/temp 等可再生成缓存、Git 数据库和无关历史产物通常排除；排除前核对项目特有依赖和必要构建配置。
- 已有 HTML 被移动或改名时用哈希确认身份。若修复仅存在于 HTML，随包保留获准交付的修复产物和最小可复现脚本/基线，并明确直接重建源工程不会自动继承该修复；不得把归档称作已同步源码。历史工具依赖未收录的历史素材时写清限制。
- 清单记录相对路径、大小和 SHA-256；归档后核验 ZIP CRC、归档内文件与来源哈希，并检查归档期间源文件是否变化。报告 ZIP 字节数、哈希、Creator 版本、恢复点及包含/排除范围。HTML 的渠道体积上限不套用到工程 ZIP。
- 提供解压后应在 Creator 打开的目录及目标场景。文件完整性通过不等于新机器 Creator 导入/构建通过；只做归档时如实说明未重导入，不为归档擅自改场景或构建入口。
